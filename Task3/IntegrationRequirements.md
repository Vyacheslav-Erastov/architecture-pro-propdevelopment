# Требования к внешним интеграциям

## Требования к безопасности

### Конфиденциальность

1. Все персональные данные (биометрические данные, номера автомобилей) должны шифроваться при передаче и хранении
2. Использование TLS 1.3 для всех соединений
3. Минимизация передаваемых данных - передавать только необходимые идентификаторы

### Целостность

1. Использование цифровых подписей для всех запросов/ответов
2. Валидация данных на всех уровнях
3. Регулярные проверки целостности передаваемых данных

### Доступность

1. SLA 99.9% для критичных операций (открытие двери, шлагбаума)
2. Резервирование каналов связи

## Протоколы аутентификации и авторизации

### Аутентификация

1. OAuth 2.0 с PKCE для мобильного приложения
2. Взаимная аутентификация между сервисами Mutual TLS 1.3

### Авторизация

1. Role-Based Access Control (RBAC). Сервсиом могут пользоваться только собственники.


## Организация взаимодействия между системами предприятия и внешней платформой

### Архитектура взаимодействия

Взаимодействие строится по схеме: Мобильное приложение -> Сервис с услугами -> Сервис интеграции -> Партнерская платформа. Сервис аутентификации и авторизации обеспечивает контроль доступа на уровне каждого запроса.

### Процесс аутентификации и авторизации

Перед обращением к сервису с услугами пользователь проходит аутентификацию в сервисе аутентификации, получая JWT-токен. Сервис с услугами проверяет этот токен и RBAC-разрешения пользователя. Только пользователи с ролью "собственник" получают доступ к функциям управления умным домом.

### Защищенные каналы связи

#### Уровень 1: Приложение -> Сервис услуг
- HTTPS с TLS 1.3
- JWT-токен в заголовке каждого запроса

#### Уровень 2: Сервис услуг -> Сервис интеграции
- Внутреннее HTTP-взаимодействие в защищенном периметре
- Сервисная аутентификация

#### Уровень 3: Сервис интеграции -> Партнерская платформа
- Mutual TLS (mTLS) с взаимной проверкой сертификатов

### Процесс работы с биометрией лиц

1. Авторизованный доступ: Пользователь с ролью "собственник" получает доступ к функции добавления лица
2. Многофакторное подтверждение: Сервис услуг запрашивает подтверждение через OTP или биометрию устройства
3. Передача данных: Сервис услуг передает запрос в сервис интеграции с полным контекстом пользователя
4. Безопасная коммуникация: Сервис интеграции шифрует фотографии и отправляет их партнеру через mTLS-канал
5. Обработка у партнера: Партнер извлекает биометрические дескрипторы, удаляет исходные фото и хранит данные в зашифрованной БД

### Процесс работы с номерами автомобилей

1. Ввод и проверка: Пользователь вводит номер автомобиля, сервис услуг проверяет формат
2. Передача запроса: Данные передаются в сервис интеграции с информацией о разрешениях доступа
3. Защищенная передача: Сервис интеграции шифрует номер и отправляет партнеру
4. Хранение и синхронизация: Партнер сохраняет номер в зашифрованном виде и синхронизирует с устройствами шлагбаума

### Просмотр и управление данными

Для просмотра своих данных пользователь обращается к сервису услуг, который через сервис интеграции запрашивает данные у партнера. Партнер возвращает информацию в маскированном виде. Полный доступ к данным требует дополнительной одноразовой аутентификации.

Удаление данных инициируется через сервис услуг, который гарантирует полное удаление как в партнерской системе, так и во внутренних системах PropDevelopment.

### Контроль и соответствие требованиям

Все операции логируются с привязкой к пользователю и сессии. Регулярные аудиты проверяют соответствие 152-ФЗ, особенно в части хранения биометрических данных. Система мониторинга отслеживает аномальные паттерны доступа и автоматически реагирует на подозрительную активность.
